# 小程序实现规划

> 背景：之前设想过「把工作台 AI 日报同步成可分享的小程序页面」，但还没有完整落地过程，故**不计入案例**，这里单独列规划，作为后续待办。
> 下面以「AI 日报小程序」为主线示例，结论可平移到其他小程序想法。

## 一、目标与范围（MVP）

- 用户打开小程序 → 看到每日 AI 日报卡片流（标题 / 摘要 / 来源 / 日期）。
- 支持：按日期浏览、关键词搜索、分享给微信好友/群。
- 暂不做：评论、账号体系、付费、后台编辑（先做只读展示）。

## 二、技术选型对比

| 方案 | 上手 | 跨端 | 适合度 | 说明 |
| --- | --- | --- | --- | --- |
| **原生微信小程序** | 中 | 仅微信 | ★★★ | 官方文档全、生态稳；需学 wxml/wxss/js |
| **uni-app（Vue）** | 低 | 微信+支付宝+抖音+App | ★★★ | 一套代码多端，适合以后想铺多平台 |
| **Taro（React）** | 中 | 多端 | ★★ | React 技术栈友好 |
| **WebView 套壳** | 低 | 微信 | ★ | 把现有 H5 页面用 web-view 包一层；**受域名校验与能力限制**，仅适合已有一致 H5 的场景 |

**建议起步**：先用**原生微信小程序**跑通 MVP（学习成本最低、坑最少）；若以后要跨端再迁 uni-app。

## 三、数据层（核心难点：内容从哪来）

小程序**不能直连**你本机的 WorkBuddy 数据（跨域 + 需鉴权）。三条路：

1. **云开发（推荐起步）**：微信云开发 = 云函数 + 云数据库 + 云存储，免自建服务器、免备案。AI 日报由 WorkBuddy 自动化/脚本写入云数据库，小程序端直接读。
2. **自有 API**：你已有后端或愿搭一个（需**备案域名 + HTTPS**），小程序 `request` 拉 JSON。灵活但运维重。
3. **静态内容（最简）**：WorkBuddy 把 AI 日报导出成 `daily.json` 托管到任意 HTTPS 静态空间（如对象存储/CDN），小程序拉这个文件。无实时写入、但零服务器。

**MVP 推荐 方案 3 → 方案 1 演进**：先用静态 JSON 验证展示与分享，跑顺了再上云开发做自动同步。

## 四、里程碑

- **M1 脚手架**：注册小程序账号、装开发者工具、建空项目、出"Hello"页。产出 `app.js/app.json/app.wxss` + 一个列表页。
- **M2 数据接入**：定义日报 JSON 结构（date/title/summary/source/url）；静态托管 + 小程序 `wx.request` 拉取渲染列表。
- **M3 体验**：日期筛选、搜索、卡片详情、分享按钮（`onShareAppMessage`）。
- **M4 自动化（可选）**：WorkBuddy 周期性任务把 AI 日报生成 JSON 并推到托管点（接方案 1 云开发或方案 3 静态），实现"日报日更"。

## 五、风险与对策

- **内容合规**：AI 生成内容需标注来源、避免未核实信息；分享出去前过一遍审核。
- **域名校验**：小程序 `request` 域名必须在后台配置白名单（需 HTTPS + 备案），本地调试要开"不校验合法域名"。
- **账号与个人主体限制**：个人主体小程序**不能**用云开发部分能力/支付/部分类目；若要做复杂功能需企业主体。
- **内容更新**：静态方案需有稳定推送通道，否则会变"过期站"。

## 六、最小可用起步路径（照做即可）

1. 微信公众平台注册**小程序**（个人主体即可），拿到 AppID。
2. 下载**微信开发者工具**，新建原生小程序项目。
3. 先做一个 `web-view` 套壳页指向你现有 AI 日报 H5（最快看到东西，验证分享）。
4. 验证通过后，按 M2 改读静态 `daily.json`，脱离 web-view 做原生卡片流。
5. 最后用 WorkBuddy 自动化把日报 JSON 自动推送，闭环。
