明天就是 1024 了。

往年这天，朋友圈基本是同一套：转海报、晒工牌、抽奖。热闹一天，第二天照常上班。

今年想干点别的。做个小东西吧，不用多厉害，能让人愿意点开第二次就行。

![](assets/shots/01-main.jpg)

## 先把方向反过来

做程序员这些年，我打开次数最多的界面，大概是告警大盘。

红的黄的，一屏一屏往下刷。半夜手机一响，看一眼就知道今天晚上别想睡了。

那个东西，只统计坏消息。

那我就做一个只统计好事的。

CR 一次通过、需求突然冻结、今天不用上线、手机整晚没响。这些事平时没人记，发生了也就发生了，第二天照常上班，跟没发生过一样。

我把它们做成一条往下滚的流。扫到哪条，点一下收进来，每件折成钱，攒进当天的奖金池。

顶上四个指标，都不扎心：离下班还有多久、今天攒了多少、今天几件好事、连着打卡几天。

红色只留给了「生产变更待确认」。就这一个。

![](assets/shots/05-board.jpg)

## 1024 不是拿来当标题的

光有个大盘太单薄。我想给它一个结构，不是一个名字。

1024 = 2¹⁰。这个数能用。

十道场景题，每题选 A 记 0、选 B 记 1，十道拼起来正好是十条二进制，转成十进制就是工号，0 到 1023。

前八位两两一组，四个维度：发布胆量、重构冲动、评审火力、需求弹性，每组后一位记程度。最后两位是装备彩蛋。

四维极性 2⁴ 出 16 型，再乘程度的 2⁴ 和装备的 2²，一型 64 个编号。16 乘 64 正好 1024，不多不少。

写文案之前我不太放心，把 0 到 1023 全跑了一遍。一型确实刚好 64 个，一个不差。

![](assets/shots/02-bitgrid.jpg)

题目也不是编的。比如这道：

「一行字改完，顺手看了眼样式：这行 CSS 挂了 7 个 !important，底下还有三段被注释掉的旧代码在互相覆盖。」

题干上标着时间和当时的心境：周四 15:30，本来只想改个按钮文案。

A 是改完就跑，假装没看见。B 是顺手删干净，再把布局重写一遍。

选哪个，会真的影响你拿到什么号。

## 六块，随便点

领到号之后，六块面板都能点开。除了前面那块大盘，另外五块大概是这些：

工牌和人设那块，上面有技能雷达、bug 体质、掉发指数。16 型各配一位封神原型，姜子牙、杨戬、哪吒这些，形象是重新画的原创手办风。

![](assets/shots/03-pass.jpg)

1024 个格子里，你在哪一格会一直闪。

![](assets/shots/04-grid.jpg)

我第一次看到自己那一格在闪的时候，还挺高兴的。

证书是四张：国家级持证摸鱼工程师、线上救火专员、祖传代码修复大师、0Bug 许愿人。名字、工号、部门都能改，钢印是画上去的，导出来是 PNG。

![](assets/shots/06-cert.jpg)

代码时光机里放了五段代码，2006 到 2018。粘一段进去，它告诉你这段代码停在哪一年，还给行级 diff 和重写版。

![](assets/shots/07-timemachine.jpg)

2006 那段是八层 for 套着写、土办法居中。翻出来的时候我自己都沉默了。

许愿机是先摇一条当引子，再改成自己的话封存，明年再开。不预测任何东西，说白了就是存个念想。

![](assets/shots/08-wish.jpg)

需求翻译机这块我最想给同行看。

把「页面再丝滑一点」「简单搞下」贴进去，它给你四栏：隐含需求、隐藏工作量、风险点、排坑提醒，再打个一到五级的危险度。

「页面再丝滑一点」翻过来是：你先定位瓶颈，再给我三个方案，2 到 5 人日，危险 3。

![](assets/shots/09-translate.jpg)

底下还有一份 24 条的黑话榜，按杀伤力排的，点一行直接翻。

![](assets/shots/10-jargon.jpg)

## 几个蠢坑

做的时候踩了几个坑，都挺蠢的，说给你乐一下。

第一个是发布。我一直以为 GitHub Pages 是从 main 推的，或者至少是 /docs，反正我见过的教程都这么写。

一查 API 才发现，这个仓库的源是 gh-pages 分支的根目录。main 完全不管事。

那个分支里还早就躺着两个应用了。行吧，一个子目录一个应用，我照着加了个 1024 就完事了。

顺带写了个发布脚本。国内 git 直连老是断，只能走 Git Data API，一个文件一个 blob 往上送。31 个文件，六百多 K。

第二个是截图。发完我截了张 1600 宽的图，看着「需求翻译机」右边像被切了。越看越像。

于是去量。六个面板的右留白全是 14，那正好是内边距，横向溢出全是 0。

就是图被缩到 1080 显示而已。字被压扁了，看着像从中间断掉。

这种亏之前吃过一次。有回我觉得某块内容全挤在左边，右边空一大片，撸袖子要改 CSS，量完发现人家居中得整整齐齐，两边各留 340。白忙。

第三个是我自己写的代码。后来要写作品介绍，得把公式写准，我就回头翻了一遍生成工号位格的那行。

那行只给第 1、3、5 个位置加了分隔。

四个维度两两一组，缝本该落在 1、3、5、7。

我把 7 漏了。

所以第三和第四个维度是粘在一块的。就 8px 的缝，截图缩到 1080 根本看不出来。上线了，图也发了，我自己盯了好几轮，都没发现。

改起来是一行的事。顺手加了条自检，以后哪次再漏，跑检查会直接报错。

顺便说一句，这东西是我和 AI 一起做的。我提，它写；我看着不对就说不对，它改。今天改得最多的是文案，同一句介绍来回磨了五版才定下来。

## 没有后端

最后说个设计上的事。

这东西没有后端，一行服务端代码都没有。数据全在你自己浏览器里，断网也能玩，不用登录，不用注册。

但这样就有个问题：同事的好事，怎么出现在同一块大盘上？

我没做账号体系。做法是点「我的票」，复制一段票码发给对方，他粘进「并入」框，就合到一起了。

票码里只有工号和好事编号，别的东西一概没有。

够用了。

另外，这里面没有任何预测的东西。工号是二进制转十进制算出来的，稀有度是数编号空间得的，祝福语是按工号和愿望算的哈希。都能复核，不是玄学。

封神那些人物取自公有领域的神话，形象是重新画的，没用任何影视或游戏的官方素材。
